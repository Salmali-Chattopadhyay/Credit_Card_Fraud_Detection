Overview

Project Objectives

This project addresses the critical challenge of detecting fraudulent credit card transactions in a highly imbalanced dataset (only 0.43% fraud). We implement the full data science lifecycle from raw data to a deployable detection model.

GOAL 01

Data Collection

Import Kaggle credit card transactions dataset. Handle privacy and security compliance.

GOAL 02

Data Exploration

Identify fraud percentage and anomalies in transaction amounts across the dataset.

GOAL 03

Preprocessing

Handle imbalance with SMOTE. Normalize numerical features for model training.

GOAL 04

EDA

Histograms, boxplots, and correlation matrices to understand feature distributions.

GOAL 05

Feature Selection

Feature importance to identify the top fraud indicators from 29 PCA features.

GOAL 06

AI Model

Random Forest model to flag suspicious transactions with near-perfect AUC.

Methodology

ML Pipeline

End-to-end pipeline from raw CSV to trained models ready for real-time inference.

Load & Merge

  • Ingest raw transaction data from multiple CSV files
  • Merge datasets into a unified structure
  • Remove duplicates and validate schema consistency

EDA

  • Analyze fraud distribution and class imbalance
  • Study transaction amount patterns and anomalies
  • Visualize correlations and feature relationships

SMOTE

  • Handle extreme class imbalance in dataset
  • Generate synthetic fraud samples using SMOTE
  • Improve model sensitivity to minority class

Normalize

  • Apply StandardScaler to numerical features
  • Ensure consistent feature scaling for models
  • Perform stratified 80/20 train-test split

Train Models

  • Train Random Forest and Logistic Regression models
  • Apply class weighting for imbalance handling
  • Optimize models for fraud detection performance

Evaluate

  • Measure AUC-ROC and Precision-Recall performance
  • Analyze confusion matrix for prediction errors
  • Evaluate precision, recall, and F1-score

Preprocessing

Handling Class Imbalance

With only 0.43% fraud, a naive model would learn to ignore fraud entirely. SMOTE generates synthetic minority-class samples using k-nearest neighbours.

SMOTE — Synthetic Minority Oversampling Technique
Training set before SMOTE: 103 fraud vs 23,809 legitimate transactions. After SMOTE: 23,809 fraud vs 23,809 legitimate — a perfectly balanced training set. SMOTE creates synthetic samples by interpolating between real fraud transactions and their k-nearest neighbours, rather than simply duplicating existing samples. This prevents overfitting to a small number of actual fraud examples.

Note on Precision vs Recall tradeoff: In fraud detection, recall is critical — missing a fraudulent transaction (false negative) is far more costly than a false alarm (false positive). The Random Forest achieves 96.15% recall meaning it catches nearly all fraud cases, while maintaining a reasonable 78.12% precision.
